# Launchpad 0.1.0 release notes

> **DRAFT. Not released.** Nothing described here is published yet: no npm package, no image, no
> tag, and no date has been set. The plan and remaining work are in
> [release 0.1.0](../plans/release-0.1.0.md). Every statement below was checked against the
> repository, not against a published artifact.

## What Launchpad is

Launchpad is a controller and dashboard around Dokku, with a CLI and an MCP server that talk to the
controller ([README](../../README.md)). The controller has operator login, organizations, members,
projects, optional email invitations and recovery, and an OpenAPI reference. Deployments (apps,
uploads, deployments, manual deletion) and stable-hostname aliases are **off by default** and are
enabled by settings (`LAUNCHPAD_DEPLOYMENTS`, and separately aliases; see
[deployments](../deployments.md)).

This is an early release. The versions are `0.x`: a minor release may contain breaking changes
([compatibility rules](../releasing.md#compatibility-rules)). The production Compose stack has
**never run as production** ([production Compose](../production-compose.md)).

## Highlights

- A production-shaped Compose stack (PostgreSQL, controller, worker, Dokku, alias router, operator
  image) that pulls released images ([install](../install.md), [production Compose](../production-compose.md)).
- Forward-only migrations on a clean v1 schema baseline; rollback is restoring the pre-upgrade
  backup ([upgrade](../upgrade.md), [restore](../restore.md)).
- Fail-closed database re-check, a `/api/ready` endpoint and worker liveness reporting.
- Client packages that run on Node (`>=22.12`) and Bun, published unbundled.
- Licensed under Apache-2.0; images carry OCI labels and licence notices.

## Published artifacts

npm packages (one shared version; `tooling/package-clients.ts`):

| Package                      | Provides                                                |
| ---------------------------- | ------------------------------------------------------- |
| `@launchpad-kit/contracts`   | Versioned API shapes (zod)                              |
| `@launchpad-kit/sdk`         | Browser-safe HTTP client for the API                    |
| `@launchpad-kit/client-core` | Profiles and credential file shared by the CLI and MCP  |
| `@launchpad-kit/cli`         | The `launchpad` command                                 |
| `@launchpad-kit/mcp`         | The `launchpad-mcp` stdio server (read-only by default) |

Images, built from this repository (`docker-compose.yaml`): `ghcr.io/launchpad-kit/launchpad-controller`,
`-worker`, `-router`, `-admin` (the operator image) and `-dokku`, tagged with the release version.
Per the release decision, `X.Y.Z` tags are never rewritten; whether `X.Y` and `latest` are moved is
**proposed, not decided**.

## Install and upgrade

- Install: [install](../install.md) and [production Compose](../production-compose.md).
- Upgrade: [upgrade](../upgrade.md). Take and verify a [backup](../backup.md) first.
- There is no previous release to upgrade from; 0.1.0 starts with an empty database.

## Platform support

- Images: Linux. **`linux/amd64` only is proposed, not decided**; `docs/install.md` is written for Linux/amd64 and no arm64 build has been tested.
- The npm packages are **POSIX only**: `client-core` checks file modes and owners and Windows is not supported and untested ([releasing](../releasing.md)).
- Licence: Apache-2.0 (root `LICENSE`).

## Migration notes

These changes are against the repository before the release preparation, not against a published
version:

- `docker-compose.yaml` **requires `LAUNCHPAD_IMAGE_TAG`** (for example `0.1.0`, or a local tag you
  built); Compose fails to start without it and there is no default.
- Images were renamed from `launchpad/<name>` to `ghcr.io/launchpad-kit/launchpad-<name>`. A local
  build must use the new name with `LAUNCHPAD_IMAGE_TAG` set to the local tag
  ([install](../install.md)).
- The Dokku image's build context is now the repository root, with
  `containers/dokku/Dockerfile` (it was `./containers/dokku`).
- `cli` and `mcp` are unbundled: they install their dependencies from the registry, and `client-core` is now a published package.

## Known issues

- Never run as production; schema rollback with a real migration delta was not rehearsed
  ([production Compose](../production-compose.md)).
- Recorded but not reproduced in the rehearsals ([follow-up](../plans/production-compose-follow-up.md)): a held promotion; a backup killed
  mid-write; `ERR_POSTGRES_CONNECTION_CLOSED` is not classified, so a connection dropped in flight can answer 500 on a request route until the next schema check.
- The image builds and `test:images` have not been verified with Docker as part of release preparation.
- Windows is not supported.
- `client-core` has non-blocking audit follow-ups.
- No ingress, TLS or Dokku backup is supplied by the stack ([install](../install.md)).
