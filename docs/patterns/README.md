# Package boundaries and patterns

For contributors deciding where controller code belongs. Keep this index and
its example paths current whenever a boundary or pattern changes.

## Established patterns

| Concern             | Pattern and example                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UI and HTTP hosting | One TanStack Start React app, built for Bun through Nitro: `apps/controller/vite.config.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| API transport       | Elysia 2 RC's fetch handler is mounted in `apps/controller/src/routes/api.$.ts`. It owns no listener.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Services            | Framework-free functions in `packages/services/src`: the role matrix (`authorization.ts`, the only source of organization authorization), organizations, members, projects and API keys (`api-keys.ts`). Every function takes the caller (`Principal`) and organization; non-members get not-found. Handlers and server functions delegate to them. Do not import Elysia, React, or Start here.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| SQL and migrations  | Kysely on Bun's native SQL client (`BunSqlDialect`), one instance shared with Better Auth, explicitly constructed in `packages/database/src/index.ts`; forward-only migrations in `packages/database/src/migrations`, run only by the explicit admin command.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Organization API    | `apps/controller/src/server/api.ts` maps `ServiceError` codes to statuses (`respond`). Better Auth's `/api/auth/organization/*` is blocked there; organization changes only go through our services. Pages read via `src/server/data.ts` server functions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| API reference       | `@elysia/openapi` mounted last in `apps/controller/src/server/api.ts`; operations are described in `src/server/openapi.ts` from the zod schemas in `packages/services/src/contracts.ts`. Scalar's bundle is published from our own origin by `vite.config.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Authentication      | Better Auth is built by `createAuth` in `packages/auth/src/create-auth.ts` from validated configuration; the Elysia adapter mounts it at `/api/auth` and guards cookie mutations by origin in `apps/controller/src/server/api.ts`. Start pages read the session through `apps/controller/src/server/session.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Tasks               | Omni runs everything: presets in `omni/presets`, repository-wide tasks and `check:deps` in `tooling/`. Project dependencies are declared in both `package.json` and `project.omni.yaml`; cache keys name every input. See `docs/tooling.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Email               | `Mailer` in `packages/auth/src/mailer.ts` (nodemailer; plain SMTP only to loopback). Invitations live in `packages/services/src/invitations.ts`; tests use the in-process `@launchpad/auth/testing` fake SMTP server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Contracts and SDK   | `packages/contracts` holds the API's roles, key scopes, input and response schemas (zod only, browser-safe); services and the OpenAPI document import them. `packages/sdk` is the bearer-key HTTP client built on them. `packages/client-core` adds profiles and the credential file for the CLI and MCP.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Previews            | `packages/services/src/previews.ts` and migration `…_010_previews`: generated Dokku app names, per-organization serialization (advisory lock), idempotency keys, and database-level invariants for deployments.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Deployments         | `packages/services/src/deployments.ts` and migrations `…_011_deployment_leases` and `…_012_rollback_intent`: the deployment row is the queue and the lease (`enqueueDeployment`, `claimNext`, `runDeployment`, `resolveReconciliation`). The `attempt` is the fencing token on every state write (`fenced`); progress is written ahead of each change (`step_pending`); a load with an unknown outcome parks the preview in `reconciliation-needed`. `getDeployment`, `listDeployments` and `listDeploymentEvents` are the read side (fixed failure text only); `enqueueDeployment` takes an idempotency key. It talks to Dokku only through the `DeployPorts` it is given. Off unless `LAUNCHPAD_DEPLOYMENTS=on` (`deploymentsEnabled`).                                                                                                                                                                                                                                                                                                             |
| Worker              | `apps/worker`: polls `claimNext` and supplies the real `DeployPorts` (`ports.ts`): fixed Nginx template (`template.ts`), re-validated extraction (`extract.ts`), a fixed docker vocabulary (`docker.ts`), and a readiness probe that checks the deployment id (`verify.ts`), and rollback of a failed verify by redeploying the previous release. Opt-in live tests: `omni -i run test:live -p @launchpad/worker`. The only holder of Dokku and Docker access. Off unless `LAUNCHPAD_DEPLOYMENTS=on`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Lifecycle           | Schema in migrations `…_013_preview_lifecycle` (expiry and deletion state tied together by checks, `deletion_operation` with one unfinished per preview, `worker_heartbeat`), `…_014_deletion_fence`, `…_015_artifact_collected`, `…_016_slug_reuse_and_instance_state` (a name is free once its preview is deleted; `instance_state` holds the first-enable marker) and `…_017_worker_heartbeat_lifecycle`. Services: `lifecycle.ts` (settings, off by default, audit names), `expiry.ts` (extension and the expiry claim), `deletions.ts` (queue, claim, run with fenced writes and the ownership pattern, resolve), `deadline.ts` (monotonic and wall-clock lease deadline), `artifact-gc.ts` (collection and the orphan sweep), `lifecycle-run.ts` (one round: grace, expiry, one deletion, collection), `status.ts`. The worker side is `apps/worker/src/lifecycle-ports.ts` (the only destroy and image-removal vocabulary). `preview:delete` is deployer and above. Off unless `LAUNCHPAD_LIFECYCLE=on` on both the controller and the worker. |
| Uploads             | `packages/services/src/archive.ts` and `artifacts.ts`: raw-body archive upload, validated while streaming; `apps/controller/src/server/body-framing.ts` applies one framing rule to the API and to `/_serverFn/**` (Nitro middleware in `vite.config.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Dokku               | `packages/dokku`: typed, allowlisted operations over ssh with a pinned host key (`client.ts`), validators (`validate.ts`), trust checks (`trust.ts`) and the transport (`transport.ts`). No generic command runner; five error kinds, of which `uncertain` must be reconciled.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| UI styling          | Skeleton 5 and Tailwind 4 imports in `apps/controller/src/styles.css`; semantic HTML and body scrolling in `src/routes/__root.tsx` and `index.tsx`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| CLI                 | `apps/cli/src/program.ts`: login, whoami, profile, org, projects, deploy, previews (list, get, extend, delete, deletion) and deployments commands over `@launchpad/client-core`, behind an `Io` interface so tests need no terminal or network; entry in `src/index.ts`. The key is never an argument. It consumes the controller, never Dokku.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Testing             | Unit tests need no infrastructure and call `api.fetch(Request)`. Integration tests (`*.spec.ts` in `__tests__`) use a disposable PostgreSQL via `@launchpad/database/testing`; `apps/controller/src/__tests__/hop.spec.ts` drives the built server over HTTP.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

The local stdio MCP adapter lives in `apps/mcp/src/server.ts`. It uses only
client-core and the SDK, never controller services or the CLI executable. Per-call
`working_dir` and `launchpad.json` context resolution lives in
`packages/client-core/src/workspace.ts`; it never changes cwd or saved selections.
The CLI's deploy command uses the same resolver. File selection for deploys (operator
include/exclude globs, exclude wins) lives in `packages/client-core/src/pack.ts`. MCP output is bounded and uses
the same `safeOutput` redaction/control stripping as the CLI (client-core).

The preview page's lifetime controls live in `routes/orgs_.$orgId.previews.$previewId.tsx` and
read through `getPreviewDetailFn`, which returns role flags (`canExtend`, `canDelete`,
`canResolve`), `deletionsAvailable`, `lifecycleEnabled`, `maxTtlSeconds` and the server's
`now` from the runtime's settings, and `preview: null` (with its deletion) for a deleted
preview. The list is the `previews.index` route so the two are siblings (a list route without an
`<Outlet/>` hides its children); its loader returns `lifecycleEnabled` and `now`. Pure wording
helpers are in `src/lib/previews.ts`; the deploy panel is `src/components/deploy-panel.tsx`,
with its three-step flow (create, upload, deploy, resumable) in `src/lib/deploy-flow.ts` over
`apiCall` in `src/lib/api.ts`; `src/lib/use-now.ts` keeps the displayed time moving from
the server's `now`.

Operator status is `getStatus` in `packages/services/src/status.ts` behind session-only
`GET /api/v1/status`; the worker's `recordHeartbeat` writes `worker_heartbeat` from a timer in
`apps/worker/src/worker.ts`.

The health endpoint reports static metadata, not PostgreSQL/Dokku readiness.
Lifecycle requests are now exposed by `src/server/api.ts`: delete and extend enforce key
scope plus project limits through `previewProjectId`; deletion reads use
`deletionProjectId`. Resolution is fresh-session-only. The services retain membership
checks after row locks. `getDeletion` explicitly selects public fields only; never return
leases, fences or transport output. The SDK exposes extension, deletion and deletion status,
not reconciliation and not the operator status.
Key administration is a dedicated organization-page component in
`apps/controller/src/components/api-keys.tsx`. It imports only browser-safe
contracts, issues through the cookie-authenticated HTTP API, and keeps reveals
out of loader data. `src/lib/api-keys.ts` distinguishes issued/rejected/uncertain
outcomes; never use the generic loader-invalidating mutation path for a reveal.
Operator login, organizations, members, projects, deployments, expiry and deletion exist, but
the controller is not yet hardened or packaged for exposure to the internet (see the production
plan in `docs/plans/production-compose-follow-up.md` and the follow-ups in
`docs/plans/milestone-5-lifecycle.md`): do not publicly expose it as a management system.

## Approved direction, not yet implemented

The controller will use PostgreSQL for metadata and SSH for privileged Dokku
operations. Application services should depend on narrow repository/adapter
interfaces rather than HTTP framework objects. Implement those interfaces when
the first real feature needs them, not as speculative generic abstractions.

Backup and restore (milestone 6), per-organization quotas, runtime logs and custom domains are
not built; see `docs/plans/application.md` and the follow-ups in
`docs/plans/milestone-5-lifecycle.md`.
